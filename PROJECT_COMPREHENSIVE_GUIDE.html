Airbnb Snowflake + dbt Pipeline

An enterprise-grade Analytics Engineering portfolio project transforming raw Inside Airbnb datasets into high-performance dimensional star-schemas and monthly aggregates, backed by automated data tests and an interactive BI reporting dashboard.

📌 Executive Overview

This project simulates a production modern data stack workflow. It implements complete ELT (Extract, Load, Transform) pipelines with dual execution compatibility: run on enterprise cloud Snowflake or 100% locally and free using DuckDB with zero cloud fees.

📥 Robust Raw Ingestion

Loads text-preserving CSV & GZIP files to Snowflake stages or DuckDB without pre-transforming, ensuring clean ELT separation.

📐 Layered dbt Modeling

Four distinct modeling tiers: Raw Sources, Staging (cleaning & casting), Intermediate (joins & revenue proxies), and Marts.

⚡ Incremental Processing

Utilizes Snowflake merge incremental strategy on the listing calendar fact model to scale smoothly with snapshot updates.

🛡️ Automated Testing

Comprehensive generic and singular SQL tests enforcing primary key uniqueness, foreign key relationships, and positive pricing.

📊 Real-time Dashboard

Interactive Streamlit BI dashboard computing KPIs, occupancy trends, host metrics, and neighborhood revenue distributions.

🆓 Zero-Cost DuckDB Mode

Custom SQL compatibility macros allowing full project execution on your laptop without needing a Snowflake trial or credit card.

📖 Project Background & Dataset

The data originates from Inside Airbnb, an independent open-data platform that publishes web-scraped data on Airbnb listings around the world under the Creative Commons Attribution 4.0 license.

ℹ️ Bundled City Snapshot: Albany, New York

The repository ships with bundled data from Albany, NY (September 14, 2026 snapshot), featuring 500 listings, 182,500 calendar rows, and 30,251 customer reviews. Any city data from Inside Airbnb with identical headers can be dropped in seamlessly.

File Name Format Volume Core Business Information
listings.csv.gz Gzip CSV 500 rows Listing metadata, host bio, property type, room classification, baseline nightly rate, location, rating scores.
calendar.csv.gz Gzip CSV 182,500 rows Day-by-day availability flags, dynamic prices, adjusted prices, minimum/maximum stay limits for 365 future dates.
reviews.csv.gz Gzip CSV 30,251 rows Guest review history, timestamp, reviewer profile id, guest review comments.
neighbourhoods.csv Plain CSV Reference Authoritative boundary list of municipal reporting neighborhoods and neighborhood groups.
⚠️ The Revenue Proxy Methodology

Because Inside Airbnb scrapes publicly visible web pages, actual guest transactions and financial checkout ledgers are not public. As is standard in analytics portfolios, this project models an unavailable-night revenue proxy: when a calendar day is marked unavailable (is_available = false), we estimate booking revenue using the effective daily price.

🏗️ Architecture & Pipeline Flow

Data progresses systematically through the Modern Data Stack layers:

1. Raw Zone (Data Storage)
Snowflake internal stage RAW.INSIDE_AIRBNB_STAGE or DuckDB table creation • Raw files loaded directly with all fields preserved as strings (VARCHAR) to prevent ingestion failures.
↓
2. dbt Staging Layer (Views)
stg_airbnb__listings, stg_airbnb__calendar, stg_airbnb__reviews, stg_airbnb__neighbourhoods • String cleaning (regex for currency $120.00 → 120.00), percent casts, boolean standardization, column renaming.
↓
3. dbt Intermediate Layer (Views)
int_airbnb__listing_enriched, int_airbnb__calendar_enriched, int_airbnb__reviews_enriched • Reporting neighborhood coalescing, price categorization (Budget/Mid/Upscale), host tenure calculation, daily revenue proxy estimation.
↓
4. dbt Analytics Marts Layer (Tables)
Dimensions: dim_listings, dim_hosts • Facts: fct_listing_calendar (incremental merge), fct_reviews • Aggregates: agg_listing_monthly_performance, agg_neighbourhood_monthly_performance.
↓
5. Consumption & BI (Streamlit App)
Interactive browser app (dashboard/streamlit_app.py) running cached SQL queries against the Marts layer for neighborhood comparisons and KPI tracking.

⚙️ dbt Model Layers & Data Models

Model Name Layer Materialization Grain & Description
stg_airbnb__listings Staging View 1 row per raw listing. Parses price, room classification, host info, and rating stats.
stg_airbnb__calendar Staging View 1 row per listing per date. Converts string boolean availability to SQL boolean.
stg_airbnb__reviews Staging View 1 row per review. Cleans review timestamps and strings.
stg_airbnb__neighbourhoods Staging View 1 row per unique neighbourhood. Drops blank source rows.
int_airbnb__listing_enriched Intermediate View Enriches listings with authoritative reporting neighborhoods and price bands.
int_airbnb__calendar_enriched Intermediate View Combines calendar dates with base prices; derives estimated_unavailable_night_revenue.
int_airbnb__reviews_enriched Intermediate View Denormalizes listing details into reviews and computes comment length.
dim_listings Marts Table Dimension table: Listing master with host details, property attributes, price tier.
dim_hosts Marts Table Dimension table: Host profile master with total managed listings, average portfolio price, reviews.
fct_listing_calendar Marts Table (Incremental) Fact table: 1 row per listing per day. Tracks daily availability and revenue proxy.
fct_reviews Marts Table Fact table: 1 row per guest review with associated metadata.
agg_listing_monthly_performance Marts Table Aggregate table: Listing-month summary (occupancy rates, active days, revenue).
agg_neighbourhood_monthly_performance Marts Table Aggregate table: Neighborhood-month summary designed for high-speed dashboard reporting.

Reusable Macros (macros/)

clean_price(col)

Uses regex to strip currency symbols ($, ,) and casts safe numeric decimals (18,2).

clean_percent(col)

Parses percentage strings (e.g., "95%") into mathematical decimal ratios (0.95).

duckdb_compat()

Defines Snowflake-specific SQL functions (like try_to_decimal) inside DuckDB automatically on run start.

🛡️ Testing & Data Quality Framework

Data integrity is guarded through two types of automated dbt tests:

Generic Schema Tests (YAML)

  • not_null: Checked on primary keys (listing_id, review_id, calendar_date).
  • unique: Enforced on all primary dimension identifiers.
  • relationships: Foreign key checks verifying that calendar & reviews link to valid listing IDs.
  • accepted_values: Room types must strictly belong to standard Airbnb categories.

Singular Custom SQL Tests (tests/)

  • assert_non_negative_prices.sql: Fails if nightly price in dimensions or calendar facts drops below 0.
  • assert_no_duplicate_listing_calendar.sql: Verifies that no listing has duplicate dates in the calendar fact table.

🚀 Step-by-Step Setup Guide

Choose your preferred execution path below:

💡 Why Choose the DuckDB Path?

Requires no account, no credit card, and zero cloud configuration. Everything runs completely on your computer inside a fast, embedded analytical database (airbnb.duckdb).

1. Open PowerShell & Navigate to Project

PowerShell 
cd "D:\Avnish\Avnish DE Projects\Snowflake_DBT_Project"

2. Set Up Python Virtual Environment

PowerShell 
# Enable script execution if restricted
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned -Force

# Create and activate virtual environment
python -m venv .venv
.venv\Scripts\Activate.ps1

# Install lightweight DuckDB dependencies
pip install -r requirements-duckdb.txt

3. Initialize dbt Profile & Load Data

PowerShell 
# Copy profile configuration
Copy-Item profiles.yml.example profiles.yml

# Ingest the 4 raw files directly into local DuckDB
python scripts/load_inside_airbnb_to_duckdb.py

4. Build All Models & Run Tests

PowerShell 
# Build dbt models (runs transformations + automated tests in one step)
dbt build --target duckdb --profiles-dir .

# Run the automated build verification script
python scripts/verify_duckdb_build.py

5. Launch the Visual Streamlit Dashboard

PowerShell 
streamlit run dashboard/streamlit_app.py

💡 Example Business Analytics Queries

The analyses/example_business_questions.sql file contains SQL queries solving key business dilemmas directly against the marts layer:

SQL (Marts Layer Queries) 
-- 1. Which neighbourhoods generate the highest estimated revenue?
select
    reporting_neighbourhood,
    sum(estimated_unavailable_revenue) as total_estimated_revenue
from {{ ref('agg_neighbourhood_monthly_performance') }}
group by reporting_neighbourhood
order by total_estimated_revenue desc;

-- 2. Which room types have the highest average nightly rate?
select
    room_type,
    avg(effective_nightly_price) as avg_price
from {{ ref('fct_listing_calendar') }}
group by room_type
order by avg_price desc;

-- 3. Who are the top 10 most influential hosts by portfolio size?
select
    host_id,
    host_name,
    listing_count,
    avg_nightly_price,
    total_reviews
from {{ ref('dim_hosts') }}
order by listing_count desc
limit 10;

🔧 Troubleshooting & FAQ

⚠️ PowerShell: "Running scripts is disabled on this system"

Windows defaults to restricted script execution. Fix it permanently for your user account by running:
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned -Force

ℹ️ Why run `--full-refresh` on new data snapshots?

fct_listing_calendar is an incremental model using Snowflake's merge strategy. If you load a new dataset snapshot without --full-refresh, old dates remain alongside new dates, multiplying row counts. Full refresh drops and rebuilds the fact table cleanly.

🔒 Git & Security Safeguards

profiles.yml and config/local_credentials.json are pre-configured in .gitignore. Never commit your Snowflake passwords, account numbers, or private API keys to GitHub.
